# `benchmark/plan/` — 验证定序册（执行提示词）

这里回答两个问题：**先验什么、后验什么**，以及**上游没过时下游该怎么办**。

本页写给**执行者**（人或模型）读，是一份可照着走完的流程；一页汇总在
[`SUMMARY.md`](SUMMARY.md)，机读的定序与阻塞关系在 [`plan.jsonld`](plan.jsonld)。

> 本页本身就是**提示词**：把它整篇交给模型，加一句「按 §3 执行，从 S0 开始」，
> 应当足以走完一轮而不需要再问人。凡是需要人拍板的地方，§6 逐条列出——**那些地方
> 不许模型代拍**。

---

## 0. 三本册子，别混着读

| 册子 | 问的是 | 参考是什么 | 谁写 |
| :--- | :--- | :--- | :--- |
| [`../registry.jsonld`](../registry.jsonld) · [`../reports/`](../reports/) | 对着**外部答案**量到多少 | 另一个码 · 解析解 · 实验 | 内核仓渲染 |
| [`../physics/`](../physics/) | 这份产出**自洽吗** | 物理定律与文档自身的定义 | `tools/benchmark-run.py` 生成 |
| **本册子** | **按什么顺序验，谁挡谁，缺口在哪** | ——（不含量到的数） | **手写** |

★本册子**不产生任何测量数**。它产生的是**顺序、阻塞判定与缺口清单**。执行它会
产生数，但那些数落进上面两本册子，不落这里。

## 1. 术语与判决

**判决六态**，按严到宽：

| 态 | 意思 | 什么时候用 |
| :--- | :--- | :--- |
| `pass` | 量到的落在判据之内 | 上游全部 `pass`，且本条实测通过 |
| `conditional` | 落在 1–3 倍容差之间，或上游为 `conditional` | 与物理校验册同一套 |
| `fail` | 量到的越出判据 | 本条实测未通过 |
| `unevaluated` | **没跑**：缺内核 · 缺参考侧 · 门跳过 | 与上游无关的不可执行 |
| `blocked` | **上游 `fail`，本条按规则不跑** | 必须写明挡它的是哪一条 |
| `blocked-unknown` | 上游 `unevaluated` / `blocked`，本条不跑 | 上游状态不明，本条的数不可归因 |

★★后三态**永不并进 `pass`**，彼此也不合并：「没跑」「被挡了」「上游状态不明」是
三件事，合并任意两件，读者就看不出这一批到底证明了什么。

**阻塞规则**（`plan.jsonld` 的 `blocking_rule`，本册子规定的工作约定）：

```
上游 pass         → 本条执行，按实测判
上游 conditional  → 本条执行，但判决上确界继承为 conditional
上游 fail         → 本条不执行，记 blocked（写明挡它的是哪一条）
上游 unevaluated  → 本条不执行，记 blocked-unknown
上游 blocked(-unknown) → 本条不执行，记 blocked-unknown（传递）
```

理由不是纪律，是认识论：S6（通量匹配）与 S8（时间演化）两处汇合上，上游有错时
**求解器照样收敛、轨迹照样吻合**——吻合本身不再是证据。在上游未过的前提下记一个
`pass`，等于把「两处错互相抵消」写成了「通过」。

## 2. 开跑之前：把这几件事落实

1. **参考库**。`$FYDOC_ORACLE` 指向 fydoc 仓的 `cases/` 树（本仓与内核仓各以一条符号
   链接 `tests/data -> …/fydoc/cases` 挂载）。取不到就停——**不要**用别的算例顶替。
2. **外置数据根**。`payload: ptr` 的四组（`-02` `-07` `-13` `-17`）本体在
   `$ITER_SCENARIO_ROOT`，ITER IDM / Internal Use。不在手边时相关条目一律
   `unevaluated`（缺参考侧），**不降格取近似件**。
3. **内核检出**。多数门在 `$FYLITE_KERNEL`（私仓）里跑；公开检出跑不了的条目记
   `unevaluated` 并写明缺的是哪一件——**按名拒绝，不拿别的算法顶上**。
4. **现状真源**。本册子声称的 `status` / `record_state` 必须与
   [`../reports/README.md`](../reports/README.md) 与 [`../physics/SUMMARY.md`](../physics/SUMMARY.md)
   对得上；不一致时**以那两处为准**，并回填本册子。

## 3. 执行流程（照此走）

**按 `plan.jsonld` 的 `has_part` 顺序**取阶段（`stage_order` 升序；支线 R · K · P
在其 `depends_on` 满足后随时可跑）。对每个阶段：

1. **判上游**。取本阶段 `depends_on` 的每个上游阶段的现判决（阶段判决 = 其条目判决的
   下确界）。按 §1 的规则决定本阶段是执行、还是整级记 `blocked` / `blocked-unknown`。
   记 `blocked` 时**必须写出挡它的条目 id**——不写，下一轮就无从解除。
2. **对每条条目**，依次做：
   - a. **解参考侧**。按 `oracle[].storage_uri` 取件，核对 `sha256`（在 fydoc 的
     `case.yaml` 里）。取不到 → `unevaluated`，写明缺哪一件，进入下一条。
   - b. **先写判据，再看数**。`criteria` 已声明 `tolerance_basis`：
     `machine_precision` 是**事前**判据（同一函数的两个实现，取 1e-9 或更严）；
     `measured_band` 的带**在第一次实测之后才写**——★事前写下的带只会被凑上；
     `reference_stated` 取参考自报精度，参考没自报就记 `unevaluated`，**不自拟带**。
   - c. **对口径**。按报告体例 §2 的四行表逐行填：解了哪几道方程 · 哪些量是喂进去的 ·
     单位与坐标标签与**径向标签**（`ρ` 还是 Miller `r`）· 符号约定（COCOS）。
     ★这张表比数更重要：绝大多数「不一致」最后落在它的某一行上。
   - d. **跑门**，记 `pass` / `conditional` / `fail`，并记零假设（不做这件事就能得到的
     平凡答案）。
   - e. **落记录**：机读的一条进内核仓登记册真源，散文报告按
     [`../reports/TEMPLATE.md`](../reports/TEMPLATE.md) 写进 `../reports/`，再由内核仓的
     `tools/benchmark-publish.py` 渲染到本仓。★公开册是**渲染件**，不要手改。
   - f. **回填本册子**：把该条目的 `status` 与 `record` / `record_state` 更新到
     `plan.jsonld`，并同步 [`SUMMARY.md`](SUMMARY.md) 的逐阶段表与缺口表。
3. **一条失败就停在这一支**。失败的是干路上的阶段时，其**全部**下游（含经 S6 / S8
   汇合的支）记 `blocked`；支线（R · K · P）的失败**只**挡它自己的下游。
4. **一轮结束**：更新 `SUMMARY.md` 的头三行计数、缺口表与豁免表；结论一句话，不外推。

### 分类：一条记录属于哪一类，由「参考是什么」决定

| 类 | 参考 | 容差取法 |
| :--- | :--- | :--- |
| **V 验证** | 同一函数的另一实现，或解析解 | 机器精度（1e-9 或更严） |
| **B 对拍** | 另一个码的一次运行 | 实测后定带，写明差在哪一笔 |
| **C 确认** | 实验 / 机构参考算例 | 物理带，取参考自报精度 |

★把 B 说成 V 是最常见的夸大：两套模型吻合到 1 % 不等于移植正确——**两个错误也能
互相抵消**。同理 V 不能替 C 用。

## 4. 豁免（唯一允许绕过阻塞的口子）

阻塞规则可以豁免，但**默认是阻塞**，且豁免必须同时满足四条：

1. **具名**：写进 `plan.jsonld` 的 `exempt_from_blocking`，有 id 和标题；
2. **限定到具体断言**：不豁免一整条记录，只豁免点名的那几条断言；
3. **写明理由**：为什么这条失败**没有物理下游**；
4. **写明失效条件**：什么情况下豁免自动作废。

现行豁免只有一条（性能门），见 [`SUMMARY.md`](SUMMARY.md) 末节。

## 5. 绝对不许

- **不许编造数**。取不到就是 `unevaluated`，未知写 `[TBD]`。`[TBD]` 会被闸子当作
  未满足，**这正是要的**。
- **不许顶替**。参考侧不在手边时，不拿另一个算例、另一个版本、另一个饱和规则的答案
  充数。★这条踩过：跨饱和规则（`SAT_RULE`）的比较曾两次被误读成物理差异，见 `V-01`。
- **不许把 `blocked` 报成 `pass` 或省略**。一条被挡住的条目不出现在统计里，等于宣称
  它通过了。
- **不许改公开册的渲染件**（`../registry.jsonld` · `../reports/*.md` · `../physics/*`）。
  改结论要改真源（内核仓登记册 / `fylite.engine.physics` 的判据册）再重渲染。
- **不许把受限本体搬进任何公开仓**，也不许从任何页面**超链** `$FYDOC_ORACLE` 下的
  数据件——一条超链接就足以发布一份受限件。数据一律经**路径 + `sha256`** 抵达。
- **不许写跨仓相对链接**。跨仓引用写成仓限定的行内代码（形如
  ``fydoc `cases/INDEX.md```）。

## 6. 这些地方必须问人，不许代拍

1. **`measured_band` 的带定多宽**——第一次实测之后定带，是一次**判断**，不是计算；
2. **一条记录归 V 还是 B 还是 C**——当参考的性质本身有歧义时（例：`-07` TOSCA 的代码
   归属是**推断**得来的）；
3. **新豁免**——§4 的四条满足与否由人判；
4. **参考侧要不要重跑**——例：`B-01` 的参考已从 FUSE 0.7.0 改钉 1.1.5，旧结论是否作废；
5. **受限件的取用**——`$ITER_SCENARIO_ROOT` 下四组的许可边界。

## 7. 一轮的产出物

| 产出 | 落在哪 |
| :--- | :--- |
| 每条记录的机读条目 | 内核仓登记册真源 → 渲染到 `../registry.jsonld` |
| 每条记录的散文报告 | `../reports/<类>-<编号>-<短名>.md`（体例见 `../reports/TEMPLATE.md`）|
| 产出自洽的判决 | `../physics/`（由 `tools/benchmark-run.py --write` 生成）|
| **顺序 · 阻塞 · 缺口的现状** | **本册子**：`plan.jsonld` + `SUMMARY.md` |
| **这一轮实际发生了什么** | **本册子**：`RUN-<日期>.md`（一轮一页，不覆盖上一轮）|

★最后一行是本册子存在的理由：前三行各自记录「量到了什么」，**没有一处记录「因为
上游没过，所以这一批的数不该被读」**。那句话必须有地方写下来。
