(fylite-pulse-design-abstract)=
# 摘要 (Abstract)

本文件描述 **放电设计页**（`pulse_design`）：`FYL-CONOPS-00` 场景 **S-L4（放电运行
设计）** 在浏览器前端的形态。这一页回答的是**「这一炮该怎么打，以及照这么打会发生
什么」**——一份脉冲脚本、三个模式、同一套视图：

- **配置 configure.** 单个时刻：0-D 工况、目标位形 → PF 线圈电流的静态反解、击穿
  场零，以及它们各自的判据。**时间轴没有**，一个时刻一个解。
- **设计 design.** 整条脉冲：相位与 `I_p`、位形轨迹（含下降沿自己的收缩比）→
  **逐通道电流与电压波形**；0-D 标量在走廊里滚动，播放头选片，平衡与剖面显示那一
  片，**解过的片与插值的片在面板上分得清**。
- **仿真 simulate.** 推进一次放电：启动开关起落（合＝上升沿，断＝受控下降沿），
  磁面与剖面随时间演化，走廊**右缘就是现在**，加热与驱动经滑块实时改变——
  **改的是未来，过去不重算**；不操作则停在定态，而**能维持多久由磁通预算说**。
  推进有**两档保真度**——0-D 集总能量平衡与 1.5-D 三通道输运推进——由一个开关切换
  （D-22）。**建模页的含时演化栏就是那 1.5-D 档**：它收敛进这一页，建模页此后不
  含时（`FYL-DESIGN-10` P-19）。

**这一页不引入新物理。** 平衡正解、静态线圈反解、前馈电压设计、0-D 演化、含时推进
与磁通预算在仓内均已存在（`fylite.scenario.design.*`、`fylite.kernel.zerod_*`、
`kernel.core_march_*` 与 `equilibrium_ladder`，浏览器侧 `zerod*` / `start` / `solve` /
`design` / `pulse` / `breakdown` / `evolve` 命令）。这一页做的是**把它们串在同一条
时间轴上**，并**说清哪一片是解出来的、哪一片是插出来的**。

**一条居中的物理裁定.** 平顶段的 PF 线圈电流**是形状反馈回路的稳态解，不是一条
冻结的时间函数**：在 **LCFS 锁定**的条件下，维持同一条边界所需的电流随等离子体
状态（`β_p`、`l_i`）而变。因此调节辅助加热时，页面上**位形不动、电流动**——这正是
「同步更新等离子体状态」在 PF 面上的正确表现，也是本设计与「设计一次、此后只播放」
的根本差别（{ref}`fylite-pulse-design-d6`）。

(fylite-pulse-design-conventions)=
# 约定与术语 (Conventions and Terminology)

实质断言携认识论状态标签（〔已确立〕已落地有证据 /〔工作假设〕方向已定待落地 /
〔开放猜想〕俟需求定型），不使用 RFC 2119 规范关键字——本文件是设计规划，规范条款
经 {ref}`fylite-pulse-design-deltas` 提案、落地时进 `FYL-SRS-01` / `FYL-SDD-01`。
缺失值记 `[TBD]`，不虚构。术语沿 `FYL-CONOPS-00`（交互档 / 批式档、装置牌）
与 `FYL-SRS-01`（场景线），不重定义。★「双宿主」一词已退役（`FYL-DESIGN-16` H-3，
用户裁定 2026-09-04）：指前端时写**多宿主**（CLI · Python 库 · 网页 · AI 面，数目不承重），
指本机与浏览器时写**两个运行时**，一致性判据写**跨运行时一致**（NR-ENV-004）。

**脉冲脚本（pulse script）**
:   一条放电的完整输入：四个相位时刻、Ip 波形、LCFS 位形波点、辅助加热与密度波形、
    限值声明、校验片清单。这一页的**全部面板都是它的视图**；它是可导出、可回读、
    可在两个运行时（本机 / 浏览器）执行的一份会话文档。

**设计栅格 / 播放栅格（design grid / playback grid）**
:   设计栅格是**求解发生的时刻集合**（波点，十至数十个）；播放栅格是**画面刷新的时刻
    集合**（密集，插值得到）。两者不是同一个网格，且用户看得见区别。

**播放头（play-head）**
:   当前时间片的指针。走廊、平衡截面、剖面、PF 波形四处共用同一个播放头；面板之间
    没有第二个「当前时刻」。

**已解片 / 插值片（solved slice / interpolated slice）**
:   已解片是**在该时刻真解过**平衡的时间片；插值片是由邻近已解片插值而来的画面。
    二者在界面上必须可区分。

**等 LCFS 反馈轨迹（equal-boundary feedback locus）**
:   在边界目标固定的前提下，逐时刻求「持住这条边界所需的线圈电流」而得到的电流
    轨迹 `I_PF(t) = I_PF(β_p(t), l_i(t); LCFS)`。它是形状反馈回路的**稳态解**，
    不含控制器增益、时滞与噪声（那些归 S-L3）。

**设计模式 / 仿真模式（design / simulation mode）**
:   设计模式里整条脉冲**已经存在**，播放头在其中来回读；仿真模式里只有**过去存在**，
    右缘是现在，未来尚未算出。两者共用脚本与内核入口，产物却是两类工件
    （{ref}`fylite-pulse-design-d11`）。

**推进步（march step）**
:   仿真模式的时间前进单位：一次 1.5-D 三通道输运步；平衡按自己的节律每 K 步真解
    一次，其间为面度规插值。

**实时倍率（real-time factor）**
:   仿真秒与墙钟秒之比。它由推进节律决定，随装置与档位而变，界面**报出**而不承诺
    1 : 1。

**世代与脏标记（generation / staleness）**
:   每个结果面板记录它是从哪一版输入算出来的；输入变了而结果未重算时，面板自报
    「过期」并说明**过期的是什么**。

(fylite-pulse-design-composition)=
# 页面的构造 (How the Page Is Put Together)

〔已确立〕一份脚本、三个模式、四类面板：

1. **共用控件**——「这一炮」（装置 · `R₀ a κ δ` · `I_p` 与相位）与「加热与驱动」。
   三个模式读同一份，每个量只有一个控件（D-20）。
2. **随模式而换的一块**——配置：求解器 · 击穿 · 单时刻；设计：波点与校验；
   仿真：启动开关 · **保真度（0-D / 1.5-D）** · Δt · 节律。**一个槽，三张卡**，
   上下两块原地不动（D-19）。保真度开关只在仿真那张卡上，因为只有它有时间在走
   （D-22）。
3. **三块视图**——平衡截面 · 剖面 · PF 通道。位置不变，**含义随模式而变**，
   并由面板上的小字说清是哪一种（D-18）。剖面那一块还随**保真度**而变：0-D 档
   它是规定剖面、1.5-D 档它是推出来的，两者不得同形同色而不加标注（D-22 推论 3）。
4. **时序走廊**——0-D 标量。它在三个模式里是三条不同的时间轴，这正是模式的定义。

〔已确立〕**当前模式始终可见**：三个模式的同名面板长得像，读者必须一眼知道自己在
哪一种时间里。它由外壳的运行态槽（⑤）给出；**切换模式的三枚键在页体顶上**，钉在
外壳正下方（{ref}`fylite-pulse-design-d23`）。

(fylite-pulse-design-decisions)=
# 设计裁定 (Design Decisions)

共用的页面纪律（折叠约定、读数带出处、判定块为一等产物等）在 `FYL-DESIGN-10`
成文，本篇按号引用不抄；外壳归 `FYL-DESIGN-11`。下面二十五条是这一页自己的。

(fylite-pulse-design-d1)=
## D-1 一份脉冲脚本，多个视图 (one script, many views)

〔工作假设〕这一页的状态是**一个对象**：脉冲脚本。相位、Ip、位形波点、加热波形、
限值声明、校验片清单都在它里面；面板不持有自己的那一份参数，只对脚本读写。

〔理由〕四条栏各持一份参数的代价已经量得到：相位时刻在 `zerod` 与 `pulse` 两处各有
一组输入框，两处填得不一样时页面不会说，而两条栏报的是**同一条放电**。共享一个控件
（平顶电流）不需要总线；共享一条**放电**需要一个对象。

(fylite-pulse-design-d2)=
## D-2 预设是脚本，不是表单缺省值 (a preset is a document)

〔工作假设〕「限制器起始 → 双零平顶 → 下降」这样的预设是仓根 `cases/` 里的一份
fyo / JSON-LD 会话文档（`cases/*.jsonld` + `catalogue.jsonld`），不是硬编码在页面里的
一组初值。读者那一侧：`fylite.engine.cases.load(<name>)` 取出来，页面工具栏**「导入 → 会话文件」**
施用——走的是 `FySession.apply`。页面上**没有算例菜单**。

〔理由〕预设写死在页面上，就只有页面能用；写成算例，Python 侧、CLI 与工具面读的是
同一份（`engine.cases`），而「换一个装置的预设」变成加一份文档而不是改一次代码。
★装置本身仍是**输入**：预设声明它假定的装置，装置牌不随包分发（FR-DATA-001）。

〔沿革〕页面上曾有算例选择器（`design-pulse-case` / `design-zerod-case`），2026-09-01
随「页面不再取算例」的裁定撤除；本条的实质（预设是文档不是代码）不受影响，变的
只是谁来递这份文档，施用走的仍是同一条 `FySession.apply`。

(fylite-pulse-design-d3)=
## D-3 相位与梯形波形由内核单源，页面不重写 (phases stay in the kernel)

〔已确立〕四相位梯形（`t_breakdown`、`t_rampup_end`、`t_flattop_end`、`t_end`）由
`kernel.zerod_waveform` 生成，Python 侧的 `scenario.waveform.from_phases` **调用它**
而不是复述它。这一页沿用这一条：相位边界决定一次运行**是什么**（斜坡率、磁通预算、
每一片被报在哪个相位名下），它只能有一个源。

〔工作假设〕**任意点波形**（用户逐点给的加热 / 密度序列，两种插值模式）今天只有
Python 一份（`scenario/waveform.py`，刻意留在宿主侧）。浏览器要做同一件事时，
按 DE-LOG-07 的棘轮走：**表化声明或下沉内核**，不在 JS 里写第二份插值——这正是
`FYL-REPORT-02` 量过的那笔已经付过一次的学费。按 `FYL-DESIGN-16` K-3，「下沉内核」
是这两条路里的终态（{ref}`fylite-pulse-design-kernel-contract`）。

(fylite-pulse-design-d4)=
## D-4 上升沿与下降沿：前馈电压设计 (feedforward on the ramps)

〔已确立〕斜坡段的问题是**电路动力学**问题：导体回路的 `M`、`R` 与被动结构决定
电压如何把电流推到位。这一段由既有的整脉冲前馈设计回答——Python 侧
`scenario.design.pulse.design_trajectory`（整条轨迹一次最小二乘，隐式欧拉动力学作为
线性等式代入消去），浏览器侧 `pulse` worker 命令（`feedforwardVoltages`，与仿真所用
的是同一套离散）。**不新写第二条设计路径。**

(fylite-pulse-design-d5)=
## D-5 下降沿是一等公民，不是上升沿取负 (ramp-down is its own problem)

〔工作假设〕下降沿有自己的自变量：位形收缩速率、X 点何时交回限制器、`dIp/dt` 的
下限（垂直位移事件余量）、磁通回收。今天页面只有一个**起始**小半径比 `a₀/a`
（`design-pulse-a0`）与收尾收缩比 `a₁/a`，下降沿的位形因此只能与上升沿对称——而实际
放电里它通常不是。

〔理由〕FR-PULSE-004 要求磁通预算把「已消耗」算清楚，而下降沿正是把磁通交回去的
那一段；把它当作上升沿的镜像，磁通账与位形账会同时错，且错得看不出来。

(fylite-pulse-design-d6)=
## D-6 ★平顶：LCFS 锁定，PF 电流随等离子体状态 (the flat top is a locus, not a constant)

〔已确立·用户裁定 2026-08-31〕平顶段的线圈电流由**形状反馈回路**决定。这一页因此在
平顶段求的不是「一条冻结的电流波形」，而是**在边界目标不变的条件下**、逐片解出的
**等 LCFS 反馈轨迹**：

```
I_PF(t) = argmin ‖ 边界(I_PF; β_p(t), l_i(t)) − LCFS_target ‖ ,   t ∈ 平顶
```

**落法分三级，按代价与精度排开**——同一个问题的精确解、线性化解与校验，三者互不
冒充：

| 级 | 做法 | 代价 | 何时用 |
| :--- | :--- | :--- | :--- |
| 精确 | 在新状态上重做**形状反解**（`scenario.design.discharge` 的退火，逐次线性化于它所站的平衡） | 每次数个自由边界解 | 档 C（显式触发）、状态大幅改变后 |
| 线性化 | `ΔI = −J⁺ · (∂obs/∂p) · Δp`，`p = (β_p, l_i)`：用**已有的**形状响应矩阵 `J = ∂obs/∂I`（`design.shape.shape_response`，中心差分真求解器）与状态列 `∂obs/∂p`，解出「把边界摆回原处」所需的电流增量 | 一次伪逆乘法（矩阵已在手） | 档 A′：拖动加热时逐片实时更新 |
| 校验 | 该片自由边界正解，报**实际得到**的边界与形状误差 | ≈1.2 s / 片 | 档 B（松手 / 选片） |

〔已确立〕`J` 已经存在且是**对真求解器**做的中心差分（不是解析摄动 GS）；缺的是
**状态列 `∂obs/∂p`**——`shape_response` 今天把 `profile`（含 `betap0`）按住不动，
只对通道求导。补它就是同一套中心差分再多两列（G-2）。

:::{warning}
**不要用 `design.start_state` 充当这一步。** 它是一次线性 isoflux 解，其等离子体是
按给定峰化填出的**丝云**、力平衡不在其中——它自己的文档第一句就说「**它不是一个
平衡**」。用它来回答「`β_p` 变了电流该怎么变」，等于用一个不含 `β_p` 的模型回答一个
只关于 `β_p` 的问题：答案会**看起来**合理，且永远不会自己报错。它的正当用途不变——
给退火一个可以站住的起始机器状态。
:::

三条推论，逐条是界面上看得见的行为：

1. **改加热 → 位形不动，电流动。** 这是「辅助加热交互调节、同步更新等离子体状态」
   在 PF 面上的正确表现；反过来，把平顶电流当成时间的函数、加热改了却一动不动，
   画的是一条**没有人会执行**的电流。
2. **越限判定必须随状态重算。** 限值约束的是电流，而电流现在是状态的函数：`β_p`
   一升，某一路可能刚好越过它声明的上限（FR-PULSE-005 的逐通道报告因此不是一次性
   结论）。
3. **这不是闭环控制。** 求的是回路的**稳态解**——谁把边界摆在那里——不含增益、
   时滞、噪声与垂直稳定回路的动力学。控制器动力学归 S-L3（FR-CONTROL-002），
   这一页不冒充它，界面用词也不得暗示它（"反馈轨迹" 而非 "闭环仿真"）。

〔已确立〕斜坡段与平顶段因此**是两个不同的问题**，界面上明写：斜坡＝前馈电压设计
（D-4），平顶＝等 LCFS 反馈轨迹（本条）。二者在相位边界处接续，电流连续由脚本保证。

(fylite-pulse-design-d7)=
## D-7 过期的是线性化，不是电流 (what actually goes stale)

〔工作假设〕D-6 的反解与 D-4 的设计都建立在**形状对电流的响应矩阵**上，而那是在某个
参考平衡上做的有限差分（旧 `scenario.design.shape.shape_response`，自 2026-09-06 归内核仓测试树）。状态漂移够大时，
该失效的是**线性化**，不是电流轨迹本身。

界面据此分两种徽章，措辞不可混：

- **「平顶 PF：随等离子体状态更新 · LCFS 锁定」**——常态，说明电流是**现在这个状态**
  的答案；
- **「响应矩阵：`β_p` 漂移 N %，建议重线性化」**——批式档动作（重做响应矩阵、必要时
  重解参考平衡）。

〔理由〕把后者写成「设计过期」，读者会以为图上的电流不是现在这个状态的——那是一句
**反向的假话**：它比不报还糟，因为它教人重算一件本来就是最新的东西。

(fylite-pulse-design-d8)=
## D-8 播放不解平衡；已解片与插值片必须可分辨 (playback interpolates, and says so)

〔工作假设〕播放头在播放栅格上走，画面由**插值**得到；平衡不在每一帧求解。已解片在
时间轴上打点，插值片的平衡截面带「插值（未解）」标注。

〔理由〕浏览器内一次 65×65 自由边界正解**实测约 1.2 s**（内核仓实测笔记
`docs/note/app-provenance.md`），播放不可能逐帧解；而一幅**看起来是解出来的**插值画面，
是本仓反复拒绝的那种缺陷——`validate-design.mjs` 存在的理由正是「不是一个错的数，
是一个被当作对的数报出来」。

(fylite-pulse-design-d9)=
## D-9 分档响应，各自声明预算 (tiers, each with a budget)

〔工作假设〕见 {ref}`fylite-pulse-design-tiers`。批式档动作**不得**由滑块触发——
这是 DE-LOG-04 的直接落点：批式任务不以交互操作的形式呈现。

(fylite-pulse-design-d10)=
## D-10 两个运行时同脚本、跨运行时一致 (one script, two runtimes)

〔工作假设〕同一份脉冲脚本在浏览器与本机（Python 侧）两个运行时执行，得到同一条 PF
波形——**跨运行时一致**，显式容差断言（NR-ENV-004）。工具面（MCP / JSON-RPC）经既有
能力目录反射，不新开执行路径（DE-LOG-06）。脚本与其产物是**自描述、未提升**的会话
文档，与 `app/assets/session.js` 既有的裁定同一条（浏览器页面产不出有身份的工件，
也不得伪造）。按 `FYL-DESIGN-16` K-6，这一判据的终态是登记册里「同一 code 在两个
后端」的一类记录（{ref}`fylite-pulse-design-kernel-contract`）。

(fylite-pulse-design-d11)=
## D-11 仿真是推进，产物是记录 (a simulation produces a record, not a plan)

〔已确立·用户裁定 2026-08-31〕仿真模式**逐步推进**一次放电：状态从当前状态前进，
**过去不可改**。它的产物是**轨迹记录**——一次运行的时序与运行清单（FR-DATA-003），
不是一份前馈波形。

〔理由〕两类工件混同的代价是具体的：一条「设计出来的」PF 波形可以拿去当参考波形，
一条「在你手动推滑块的过程中长出来的」电流不能——后者是**这一次**驾驶的结果。
界面用词、导出文件名与运行清单的 `kind` 字段三处都要把它们分开；一次仿真被当成
设计交出去，是这条线最容易犯且最难回收的错。

(fylite-pulse-design-d12)=
## D-12 滑块自当下生效，过去不重算 (a slider edits the future)

〔已确立·用户裁定 2026-08-31〕仿真模式里推动加热 / 驱动滑块，等价于在**当前时刻**
给该路波形追加一个新的设定点：`t < t_now` 的历史保持原样，`t ≥ t_now` 采用新值。

〔理由〕这与设计模式的滑块**语义相反**（那里改的是整条波形，全程重算），所以必须
明写：一个把过去也一并改掉的仿真，等于每拖一次滑块就换了一条放电，而屏幕上却还是
同一条曲线在长——用户会以为自己看到的是因果，其实是重画。界面在滑块改动处打一条
标记（概念图 ④ 的「滑块改动点」），让因与果在同一张图上可对齐。

(fylite-pulse-design-d13)=
## D-13 三层节律，实时倍率报出而不承诺 (three cadences, and an honest clock)

〔工作假设〕仿真模式有三层各自独立的节律，界面分别报出：

| 层 | 节律 | 依据 |
| :--- | :--- | :--- |
| 输运步（热 / 粒子 / 电流三通道） | 每步 **≈12 ms** 量级 | 1.5-D 步的实测量级（`docs/guide/browser-app.md` 的「已解：41 点，12 ms」） |
| 平衡真解（自由边界 + 重追面度规） | 每 **K** 步一次，单次 **≈1.2 s** | 65×65 自由边界解实测（内核仓实测笔记 `docs/note/app-provenance.md`） |
| 画面帧 | 与前两者解耦，按帧插值 | D-8 的同一条纪律 |

〔已确立〕由此**实时倍率不是 1 : 1**，也不该假装是：界面把「仿真 1 s / 墙钟 N s」
报在外壳的运行态槽（⑤，D-23），并在磁面上标明这一帧是**真解**还是**度规插值**。
★把插值帧当作解出来的磁面播放，是 D-8 在仿真模式里的同一种失败，且更隐蔽——
因为画面在动。

(fylite-pulse-design-d14)=
## D-14 PF 两档驱动：形状反馈 或 按设计的前馈电压 (two ways to drive the coils)

〔工作假设〕仿真模式给线圈两档驱动，二者不得默认混用，界面明示当前是哪一档：

1. **形状反馈（等 LCFS）**——与 D-6 同一机制：边界目标锁定，电流随状态更新。
   用来看「若形状控制到位，这次驾驶需要多少电流」。
2. **按设计的前馈电压驱动**——把设计模式产出的电压波形接进自由边界演化与回路方程
   （`code/pulse` 的电路与自由边界核对；旧 `scenario.control.evolution` 自 2026-09-06 退役，FR-MODEL-002）。用来看「**照这份设计开**，位形会
   漂到哪里」。

〔理由〕第二档正是设计的检验：前馈是在某个假定的 `β_p` 上算出来的，真实推进里状态
一变，位形就漂——**漂多少**是这条线最该给出的数，而它只有在这一档里看得见。两档
并存、且各自说清自己是什么，比给一个「都对」的混合驱动有用得多。

(fylite-pulse-design-d15)=
## D-15 复用既有的含时演化，不新建第二条推进路径 (reuse the march)

〔已确立〕浏览器与 Python 侧都已有含时推进：`core_march_init / next / result`
（三通道同步推进、可选自适应步长）与 `equilibrium_ladder`（每 K 步重解自由边界并
重追逐面度规），建模页的**含时演化栏**跑的就是这条路。仿真模式**不新写推进器**，
它做的是把这条推进挂到**放电时间轴**上，并接上 PF 走廊、驱动滑块与运行记录。

〔已确立·用户裁定 2026-08-31〕**复用的落法**：那条栏**搬进来**，成为仿真模式的 1.5-D
保真度档（D-22）。「复用」因此不是「调用同一个内核入口」这种弱意义上的复用，而是
**同一条栏换了页**。

〔理由〕DE-COMP-04 的不变式：场景入口只组合既有能力，禁止内联新数值实现。一个
「为仿真模式写的」推进循环，会在第一次数值分歧时变成两套物理——这正是本仓反复
拒绝的形状。

(fylite-pulse-design-d16)=
## D-16 启动开关：相位是结果，不是输入 (the switch decides the phase)

〔已确立·用户裁定 2026-08-31〕仿真模式由一个**启动开关**驱动，相位是它的结果：

| 开关 / 状态 | 发生什么 |
| :--- | :--- |
| **待机** | LCFS 目标与 Ip 目标可随意调；等离子体尚不存在 |
| **开** | 起放电：按 Ip 目标与声明的上升斜率走上升沿；到达目标电流即转入**平顶** |
| **平顶（运行中）** | 形状反馈持住 LCFS，驱动由滑块给；相位标签是**推出来的**，不是时刻表 |
| **关** | 进入**受控下降沿**：按声明的下降斜率与位形收缩规则退场（D-5 的自变量在这里用上） |
| **结束** | 只能**重置**，不能"再开"续上——等离子体已经没了，续上就是另一次放电 |

〔已确立〕**「关」不是急停**：它是受控下降，按斜坡率与位形规则走完。破裂与缓解不在
这一页（{ref}`fylite-pulse-design-out`）。

〔工作假设〕两模式对"相位"因此有**两种来源**，界面必须写明当前这一条是哪一种：
设计模式读四相位梯形（`kernel.zerod_waveform`，D-3 不变）；仿真模式**不读**它，
相位由开关与斜坡率推出。★把推出来的相位再写回脚本的相位字段，会让一次驾驶看起来
像一份计划——两类工件的界限（D-11）正是在这里最容易破。

〔工作假设〕**Ip 调节图在仿真模式里保留**，但它给的是**目标**：走廊上因此有两条线
——目标与实现。过渡期若实现值只是"受斜坡率限制地跟随目标"、而不是由 OH 电压驱动
电流扩散得到，界面**必须标明**这一点（G-16）；两条重合的线若其实是同一条，画它就是
在骗人。

(fylite-pulse-design-d17)=
## D-17 无操作即定态；能维持多久由磁通预算说 (steady state is a model property)

〔工作假设〕输入恒定时推进收敛到**定态**（模型的不动点）：状态在阈值内不再变，
走廊上是几条平线，界面标注「定态（Δ状态 < 阈值）」而不是让用户从平线自行猜测。

〔已确立〕**但机器不能永远平顶**：能维持多久由**磁通预算**决定——剩余可用摆幅 ÷
平顶环电压 = 可维持时长（FR-PULSE-004 的量，页面已有）。界面把余量与预计可维持
时长与定态标注**并排**显示，耗尽前预警。

〔理由〕「不操作就不变」是**模型的性质**，不是机器的承诺。一个可以无限平飞的仿真
会教出一种错误直觉，而这条直觉恰好是放电设计里最贵的那种错。★余量耗尽后**不自动**
转下降沿：自动等于替用户做决定，而这条线的整个立场是把决定留给用户、把后果摆在
他面前。（愿意让它自动的，是一个默认关闭且明写的开关。）

(fylite-pulse-design-d18)=
## D-18 模式是时间轴的含义，不是三个工具 (a mode is what the time axis means)

〔已确立〕这一页有三个模式，切换的是**时间轴的含义**：

| 模式 | 时间轴 | 「这一片」是 | PF 通道是 |
| :--- | :--- | :--- | :--- |
| **配置 configure** | 没有——一个时刻，一个解 | 你选的那一个时刻 | 一组电流（一个时刻的反解） |
| **设计 design** | 整条已存在，播放头来回读 | 播放头所在的片；解过的才是解出来的 | 整条前馈波形 + 逐通道用量 |
| **仿真 simulate** | 只有过去，右缘是现在 | 现在；边界是上一次真解的那一条 | 每个平衡节拍一个点，不连线 |

〔已确立〕**共用**的是：装置、位形、`I_p`、相位、加热与限值这**一份脚本**，以及
截面、剖面、PF **三块视图**。三个模式因此不是三个工具，是同一页的三种读法。

(fylite-pulse-design-d19)=
## D-19 切模式不重排页面 (switching a mode moves one card, not the page)

〔工作假设〕模式专属的控件收在**一个槽**里（配置＝求解器 · 击穿 · 单时刻；
设计＝波点与校验；仿真＝启动开关 · **保真度（0-D / 1.5-D）** · Δt · 节律，
D-22）；槽的上下两块——「这一炮」与「加热与驱动」——**原地不动**。

〔理由〕读者的空间记忆是一个页面最便宜的资产，而每重排一次就作废一次。三块视图
（截面 / 剖面 / PF）位置不变、含义随模式而变，这一点由面板上的那三行小字说清，
不靠布局暗示。

(fylite-pulse-design-d20)=
## D-20 一个量一个控件 (one quantity, one control)

〔已确立〕「这一炮」的每一个量——装置、`R₀ · a · κ · δ`、`I_p`、相位、加热、限值
——在这一页上**只有一个控件**，三个模式读的是同一份。

〔理由〕同一个量有两个控件，就会有两个答案，而页面不会说是哪一个。这不是假想的
失败：放电设计的几何曾经是「每条功能栏各一份」，装机时由同一份装置描述播种
（实测 `a = 0.45` 对 `0.445`），此后各走各的——于是同一页会拿一个等离子体判「能不能
放」、再给另一个等离子体设计线圈。共用控件因此住在模式**之外**：一个模式收起自己
那张卡片时，不该把别的模式的输入一起带走。

(fylite-pulse-design-d21)=
## D-21 页面定名 `pulse_design`，目录定名 `pages` (what things are called)

〔已确立·用户裁定 2026-08-31〕这一页名为 **`pulse_design`**
（`app/pages/pulse_design.html`，部件 / 功能栏 id 同名）。★它落地时会**碰到一条
闸子的字母表**：`validate-site.mjs` 当时按 `tool-([a-z]+)` 与 `data-part="([a-z]+)"`
取 id、按 `qr-[a-z-]+\.svg` 认 QR，下划线不在其中。那三处正则编码的是「id 带前缀、
全小写」，不是「不许有下划线」——落地时把字母表放宽到 `[a-z_]`，并在闸子里写明这
一句，而不是为了迁就正则改一个已经定下的名字。放宽的实况（第三处曾漏、已补）见
{ref}`fylite-pulse-design-asbuilt-app`。★逐页 QR 今天已不存在：站点只有一张
`assets/qr-site.svg`，`validate-site.mjs` 断言每页带的是同一张站点码。

〔已确立〕页面目录从 `app/scenario/` 迁往 **`app/pages/`**（复数）：它装的是站点的
**若干**页面，与 `assets/` · `devices/` · `tests/` · `figures/` 同一姿态；单数
`page/` 读作「那一页」，在一个装着多份文件的目录上是错的。目录名同时撤掉了旧假设
——「一个场景一页」正是这次合并要合掉的那一条。

〔已确立〕装置数据页同批收入该目录并定名 **`data`**（`app/pages/data.html`）。
★它一度改叫 `browser`，随即撞上仓里既有的两处：`app/guide/browser.html` 是用户
指南里讲「浏览器前端」的那一章，而 `browser-app.md` 里随之出现了「除 `browser`
一页外，站点上的一切都在浏览器内算完」——一句自己绕自己的话。`data` 与导航标签
「装置数据」对齐，也与 design / model / analysis / pulse / sim 同为「这一页干什么」
的单词。

(fylite-pulse-design-d22)=
## D-22 ★保真度是一个开关，不是第二个页面 (fidelity is a switch on one time axis)

〔已确立·用户裁定 2026-08-31〕**一个应用只有一条时间轴，它是这一炮的。** 仿真模式
的推进因此有**两档保真度**，由一个开关切换：

- **0-D 档**——`zerodb` 的集总能量平衡（`dW/dt = P_heat − W/τ_E`，D-17 所依赖的
  那个不动点）；整条轨迹一次调用 **1–3 ms**。今天跑的就是这一档。
- **1.5-D 档**——`core_march_*` 三通道推进 + `equilibrium_ladder` 每 K 步重解自由
  边界；单步 **≈12 ms**，平衡真解 **≈1.2 s**。

〔已确立·用户裁定〕1.5-D 档**不是新写的**：建模页的**含时演化栏收敛进这一页**，
它就是这一档本身。建模页此后**不含时**，只解定态与边界（`FYL-DESIGN-10` P-19）。

〔理由〕这正是 D-15 说的那件事——「不新写推进器，把既有推进挂到放电时间轴上」。
{ref}`fylite-pulse-design-asbuilt-app` 记的那处偏离由此**收口**：0-D 不是被替换掉的
临时物，它是两档里**快的那一档**；1.5-D 也不是新路，它是**换了页的那条栏**。

〔工作假设〕**推论 1——开关换的是方程，不是页面。** 同一份脉冲脚本、同一组作动器、
同一条走廊、同一个启动开关与相位机；换的只是**推进状态的那个方程**。所以它是
**保真度**开关，与 D-18 的模式开关是两件事：模式换的是**时间轴的含义**，保真度换的
是**时间轴上跑的东西**。两个开关同时在页面上，各自标明自己换的是什么。

〔工作假设〕**推论 2——档位差三个数量级，节律随之改。** 实时倍率、画面节律与平衡
节拍在两档下不是一回事；页面照 D-13 **报出而不承诺**，并且在切档时**重报**，不留着
上一档的数字。

〔工作假设〕**推论 3——1.5-D 独有的面板在 0-D 档必须空着并说明。** 剖面、χ、台基、
通量匹配、束与 LH 沉积、锯齿——0-D 档**没有这些**。**不得**用同一时刻的 0-D 规定
剖面顶替它们而不加标注：那会让读者把一条按峰化参数摊出来的曲线读成推出来的剖面。
这是这条开关引入的**新的一种静默失败**，也是它最该被闸子守住的地方
（{ref}`fylite-pulse-design-gates` 第 6 条）。

〔工作假设〕**推论 4——记录带档位。** 一份运行记录必须写明它是哪一档产生的；两档的
轨迹**不得**在同一张比较图里不加标注地并置——它们不是同一个模型的两次运行。

〔工作假设〕**推论 5——0-D 档保留，不作过渡态。** 拖着滑块要即时反馈时它是唯一够快
的一档（档 A 的预算是 ≤ 50 ms / 帧），磁通预算与相位机也已建在它上面。把它当作
「1.5-D 落地前的将就」会在落地那天丢掉交互档本身。

## D-23 ★外壳报状态，页体放开关 (the shell reports, the body switches)

〔工作假设〕**当前模式在外壳上始终可见（⑤ 槽），而切换模式的那三枚键在页体顶上**，
钉在外壳正下方。**⑤ 槽读，页体顶上的三枚键写**——两个要求都满足，且不必往外壳上
加第四个槽（那会破坏 V-12 的「四页只差三个槽」）。

〔已确立·实测〕开关在页体里：`#pulse_design-modes` 是 `<main>` 里的一块
`page-shared` 面板，在两块共用控件之下（正本 `app/pages/pulse_design.html` 与 v2 页
`page_pulse_design.html` 同）。v2 页上它已钉到外壳正下方：`app/assets/shell.js` 给
这一块加 `.shell-modes`，`shell.css` 定 `position: sticky; top: var(--shell-h)`。
⑤ 槽以模式名开头**未落**（G-22）。

〔理由〕三条：

1. **外壳要能被一处生成。** 四页共用一段代码是 V-12 的实质；一旦允许某一页往上面
   插自己的控件，「共用」就退化成「长得像」——F-2 记的正是那种退化。
2. **「始终可见」由 ⑤ 槽给足了。** 读者要的是「我现在在哪一种时间里」，那是一句
   话，不是三枚按钮。
3. **开关钉在外壳正下方，滚动时同样不消失。** 代价只有 46 px，且它属于页体，
   因此不影响另外三页。

〔沿革〕v1.2 及以前两处写「模式开关在标题栏，当前模式始终可见」——那句把「始终
可见」与「开关在哪」捆在了一起，而 `FYL-DESIGN-11` V-11 已为计算键 / 运行态把同一
形状的两件事拆开（一个是写、一个是读）；v1.3 据此改口，v1.4 实测确认开关本来就在
页体里，「在标题栏」说的是意图不是实况。

## D-25 ★每一种状态都带一个非颜色通道 (colour is never the only channel)

〔工作假设〕这一页画出的每一种状态，除颜色之外**必须还有一个通道**——形状、线型、
底纹、位置或文字。这是 `FYL-DESIGN-11` V-8 第 3 条在本页的清单化（提案 NR-QUAL-004，
正本在 `-11`）。

〔已确立〕本页的全表见 {numref}`fig-fylite-pd-vocab`（{ref}`fylite-pulse-design-vocab`）。

〔理由〕这一页比另外三页更需要这条，原因具体：**它画的东西里有一半是「这个数
可信到什么程度」而不是数本身**——已解还是插值（D-8）、前馈还是随状态（D-14）、
限值是真的还是你给的（as-built）、线性化过没过期（D-7）、未来算没算（D-11）。
这一类信息一旦只靠颜色，页面截进汇报里、打印出来、或者读者是色觉差异者时，
**它说的就不是「不确定」，而是什么也没说**。

〔工作假设〕由此三条具体约束：

1. **已解 / 插值用填充与形状**（实心圆点 + 轴上刻线 / 空心圆环），不是深浅两个蓝。
2. **前馈 / 随状态用线型**（实线 / 同色虚线），**不换颜色**——因为颜色在这里已经
   被占用了：`--coil` 紫说的是「这是线圈电流」，换掉它就等于说这是另一种物理量
   （V-8 第 2 条）。
3. **越限、限值缺失、线性化过期这三种「有问题」的状态各带文字**，而不是共用一个
   橙色。三者的处置完全不同：越限要改设计，限值缺失要补装置牌，线性化过期要重算
   响应矩阵。**一个颜色说三件事，等于一件也没说。**

它与 A / A′ 的区别不在耗时，在**谁在推进时间**——S 档里时间自己在走，用户的输入是
对**未来**的干预（D-12）。

〔工作假设〕**S0 与 S1.5 的差别不止是慢。** S0 每步解的是一个标量不动点，S1.5 每步

(fylite-pulse-design-phasing)=
# 分期 (Phasing)

〔工作假设〕每期以**一条可运行的最小闭环**为完成判据（`FYL-CONOPS-00`
覆盖深化的判据口径），不以方法族齐全为判据：

- **P0 脚本与播放.** G-1 · G-3 · G-7。判据：载入一个预设 → 拖动加热 → 走廊在预算内
  重画 → 停在任一片能看到该片的剖面，且插值片自报「未解」。
- **P1 平顶随状态.** G-2 · G-5。判据：改加热后**位形误差不增**（RMS ≤ 容差）而 PF
  电流轨迹改变，越限判定随之重报；下降沿有自己的位形自变量并进入磁通账。
- **P2 两个运行时与门禁.** G-4 · G-8 · G-9。判据：同一脚本两个运行时同波形（跨运行时
  一致，容差断言）；每个入口声明响应预算并随能力目录发布。
- **P3 仿真模式（可与 P1 并行）.** G-10 · G-11 · G-12 · G-13 · G-14 · G-15。判据：
  摆好 LCFS 与 Ip 目标 → **合开关**起放电、走上升沿、进平顶；运行中推一次滑块，
  **其前的时序逐点不变**而其后的走向改变；**不操作**则状态在阈值内定住而磁通余量
  在减；**断开关**进入受控下降沿；磁面每帧标明真解 / 插值；结束落一份标着「运行」
  的清单。
- **P4 两档驱动对照.** D-14。判据：同一份设计在「形状反馈」与「前馈电压驱动」两档
  下各跑一次，位形误差随时间的两条曲线同图可比——**设计的检验就是这张图**。
- ~~**P5 收成一页 `pulse_design`**~~（★已完成，2026-09-01）. D-18 · D-19 · D-20 · D-21 ·
  G-18。判据：一页跑通三个模式，「这一炮」的每个量只有一个控件（闸子按 id 数，不按
  眼睛看）；切模式只换那一块卡片（上下两块的 DOM 不重建）；旧的三个入口在新页通过
  同一套闸子之后撤下，站点表同批更新——★撤的只是入口，内核入口一字不动（`site.js`
  撤「控制仿真」时写的就是这句）。
- **P6 1.5-D 保真度档（含时演化栏迁入）.** D-22 · G-19 · G-20。判据：保真度开关拨到
  1.5-D 后，同一份脚本按**既有** `core_march_*` + `equilibrium_ladder` 推进（闸子
  断言页面没有第二套推进循环）；剖面、χ 与台基在这一档有值、在 0-D 档**空着并说明**；
  运行记录带档位，两档的轨迹不得无标注并置。★这一期与建模页的 `FYL-DESIGN-10` P-19
  是**同一次搬迁的两面**，同批落地：栏从建模页移出与它在这一页出现，不能只发生一半
  ——只移出会丢掉能力，只出现会有两份含时演化。

★页面改走文档门（{ref}`fylite-pulse-design-kernel-contract`）不在本表：它是
`FYL-DESIGN-16` 的分期 P1，与本表各期正交。
