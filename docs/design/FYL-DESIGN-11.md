# 摘要 (Abstract)

本文件规划 **fylite 桌面版应用的视觉设计**——不是四个页面各自的信息架构（那是
`FYL-DESIGN-09` / `-10` / `-12` / `-13` 的事），而是**四页共用的那一层：外壳**。

桌面版是内核仓 `FYL-REPORT-05` §3b 裁定并已落地的形态：

> **一个可执行文件**，内嵌整个 `app/`（89 个资源），启动后在**回环地址**上伺服
> 自己内嵌的字节，拉起**系统浏览器**；渲染用**用户自己的浏览器**，程序只做伺服。
> 实测 Linux 5.3 MB、Windows 交叉编译产物 5.9 MB（PE32+ x86-64）。

由此得出本篇的**第一条、也是最硬的一条约束**：**没有窗饰可以设计**（V-1）。没有
标题栏、没有菜单栏、没有托盘、没有原生控件。所以「桌面版应用的外壳」只能是
**页面里那一层**——而这恰恰把问题变得具体：

> **四个功能页面共用的那条带子该是什么样，四页之间又只该差多少？**

本篇分四部分回答：

- **外壳**（{ref}`fylite-visual-shell`）——V-11 把分散在两处、且**两处都会滚走**的
  页眉与工具条收成**一条常驻的两行 header toolbar**；V-12 规定四页在它上面只差
  **三个槽**；V-13 给出桌面的定尺 **16:9** 与一条可判的首屏判据。这三条**已落在
  `app/pages/page_*.html`，尚未提为正本**（{ref}`fylite-visual-asbuilt`，G-9）。
  V-2 仍是本篇的居中缺口——桌面里说错了的话。
- **四个功能页面**（{ref}`fylite-visual-pages`）——同一条外壳、四种页体，各一张
  16:9 预览图；分工线是 V-15。
- **不随宿主改变的那一层**（{ref}`fylite-visual-invariant`）——主题三态（V-5）、
  色板对物理量的语义绑定（V-8）、字级级数与行长（V-9）、不引 Web Font（V-10）。
  **桌面不是重做视觉的借口**：这些每一条背后都有一次实测或一条裁定，换个投递面
  不改变它们的理由。
- **预览图**（{ref}`fylite-visual-previews`）——V-14：它们是**生成物**，16:9、
  不带固定尺寸、由闸子守着不许手改。

〔已确立〕本篇**不规划原生窗口**（Tauri / wry + WebView2）。`FYL-REPORT-05` 的
候选表把它判为「后续可选」——依赖 WebView2 运行时、实务上要 Windows runner；
为一个**还不存在的宿主**规划窗饰，写出来的每一条都无从验证。若将来采纳，本篇按
`V-` 编号增补一节，而不是重写。

# 约定与术语 (Conventions and Terminology)

实质断言携认识论状态标签（〔已确立〕已落地有证据 /〔工作假设〕方向已定待落地 /
〔开放猜想〕俟需求定型），不使用 RFC 2119 规范关键字。缺失值记 `[TBD]`，不虚构。
裁定编号取 **`V-`**（visual），与 `FYL-DESIGN-09` 的 `D-` 及四页文档的 `P-` 分开
——三套编号同名会让「按编号引用某条裁定」的注释悄悄指错文件。

**桌面版 / 站点版（desktop / site）——本篇的「宿主」**
:   同一份 `app/`，两个**投递面**。桌面版＝`fylite` 可执行体在
    `http://127.0.0.1:<port>` 上伺服内嵌字节；站点版＝同样的字节由
    `https://fusion-yun.github.io/fylite/` 伺服。**页面的字节是同一份**，因此
    「桌面版的视觉」只能是**页面在运行时知道自己在哪**之后所做的那一点差别。
    本篇说「宿主」「宿主槽」「宿主探测」时，指的都是这两个投递面（`data-fy-host`
    的取值 `site` / `desktop`）。★它与 `FYL-DESIGN-16` H-3 的「多宿主」不是同一个词：
    那里的宿主是**前端**（CLI · Python 库 · 网页 · AI 面），网页是其中一个前端，
    桌面版与站点版是这一个前端的两个投递面。旧文的「双宿主」一词已退役（H-3）。

**外壳 / 页体（shell / body）**
:   外壳＝四个功能页面上由一处生成的那条带子（V-11 的两行 header toolbar）加页脚
    身份带；页体＝那条带子以下、随页面而异的一切。**这条线就是本篇与四份页文档的
    分工线**（V-15）。

**功能页面 / 散文页（function page / prose page）**
:   功能页面四个——装置数据、放电设计、物理建模、实验分析，各有输入、计算与输出；
    散文页三个——入口、能做什么、致谢，只有文字。**散文页没有作业，所以外壳的
    第二行在它们上面不出现**（V-12）。仓里另有一页算例报告（`report`），它不在本篇
    的四页实测之内（{ref}`fylite-visual-asbuilt`）。

**仪器面 / 文档面（instrument face / document face）**
:   本站两套排版，各有各的对。仪器面是场景页的面板、工具条、读数、图注
    （12–13 px 是对的）；文档面是散文页与场景页顶部的引言（`.doc` 作用域，
    16 px / 1.75 / `--measure: 44rem`）。**门禁只管文档面**，并明写它对仪器面
    没有意见（`app/tests/validate-typography.mjs` 抬头）。

**身份带（identity strip）**
:   页脚那一行：标记 · 其他页面 · 语言 · 版权 · **版本片** · 二维码。版本片取自
    生成物 `assets/version.js`，与内核发布号同源、不能漂移。

**正本 / 对照组（canonical / control）**
:   正本＝站点与查看器今天送出去的 `app/pages/<id>.html`；`page_<id>.html` 是由它
    生成的 v2 外壳页。在外壳被提为正本之前，原页面既是生成的**源**，也是量新页面的
    **对照组**（{ref}`fylite-visual-asbuilt`）。

(fylite-visual-baseline-shell)=
## ★外壳的实测：三条发现

〔已确立·实测 2026-09-01〕视口 **1600 × 900**（16:9），四个功能页面（正本）各测
一遍，中文语言、浅色主题、`networkidle` 后再等 1.2 s。

:::{table} 四个功能页面（正本）的外壳几何。偏移量以文档顶为原点，单位 px。
:name: tbl-fylite-shell-measured
:align: left

| 页面 | 页眉高 / 定位 | 页内工具条 | 首条功能栏 | 首处输出 | 整页高 |
| :--- | :--- | :--- | ---: | ---: | ---: |
| 装置数据 | 65 · `static` | **没有** | — | **无** | 3844 |
| 放电设计 | 65 · `static` | y = 386，高 121 | 1265 | **无** | 2212 |
| 物理建模 | 65 · `static` | y = 277，高 178 | 971 | 1327 | 6364 |
| 实验分析 | 65 · `static` | y = 277，高 121 | 412 | **553** | 6202 |
:::

由这张表得三条发现，它们是本节以下全部裁定的依据：

**F-1 ★今天没有一样东西是常驻的。** 页眉 `position: static`，页内工具条也是——
两者都在第一屏之后滚走，而页高是 **2212 到 6364 px**。在建模页上，你按下的那个
计算键与它的状态行、进度条相隔 **五千多像素**：★**计算键在功能栏里，进度与状态
却在页面工具条上**，而一次运行开始之后，唯一能告诉你它在跑的那两样东西都不在屏上。
这不是「不够整洁」，是一次运行没有可见的反馈。

**F-2 「共享」工具条只被三页共享，而且三页也没长成一样。** 装置数据页**从来没有
过**一条 `.panel.toolbar`——它的同一件事（选数据源）长在左栏的一个面板里。剩下三页
虽由 `scenario.js` 的 `buildToolbar()` 同一段代码生成，宽度却不一致：建模页用页内
一条 `max-width: 260px` 把装置下拉收窄，分析页没有这条补丁，同样一个四项列表在那里
**摊到 1086 px**。**同一段代码生成、靠页内补丁调形**，就是下一次改动会漏掉一页的
那种共享。

**F-3 四页里三页的 16:9 首屏内没有任何输出。** 首处输出（高于 40 px 的画布或表格）
在建模页是 1327、在设计页与数据页**整整 1500 px 内一处也没有**，只有分析页是 553。
第一屏给出的是：引言散文、工具条、共用输入控件。**一个计算工具的第一屏没有一个数**。

〔已确立〕另有两处与版面预算有关的实测，写在这里备用：页眉中段那条警示的**包裹
元素**宽 832–919 px，而它里面那枚橙色药丸只有 **326 px**——**中段有五百多像素是
空的**；右端导航（四枚图标 + 主题）共 **166 px**。也就是说，把作业那一行并进页眉
所需要的横向预算，页眉自己就有。

★这三条发现今天**仍对正本成立**：正本页面自 2026-09-01 起一字未动，改动全部落在
`page_*`（{ref}`fylite-visual-asbuilt`）。

## V-1 桌面版没有窗饰可以设计 (there is no chrome to design)

〔已确立〕渲染引擎是**用户自己的浏览器**；`fylite` 只伺服字节，不创建窗口、
不控制标题栏、不画菜单。因此本篇能规划的只有**页面内那一层**——与站点同一层，
同一份字节。

〔理由〕这不是遗憾，是这条通道被选中的原因之一：`FYL-REPORT-05` 的候选表里
Electron 是 150 MB+（与「单机轻量」的资源包络冲突），Tauri 要 WebView2 运行时。
换来的 5.3 MB 与「一条命令交叉编译」，代价正是**放弃窗饰**。把这条写在最前面，
是为了让后面每一条裁定都落在**真能改的东西**上。

〔工作假设〕**推论——桌面版的「外壳」有两层，而只有里面那层归我们管。** 外面那层
是浏览器标签页，我们能碰的只有 `<title>` 与 `favicon`（二者今天都随站点，
见 {ref}`fylite-visual-g4`）；里面那层就是本节 V-11 说的那条带子，**它才是用户会
认为「这个程序长什么样」的东西**。

## V-11 ★外壳收成一条常驻的 header toolbar (one strip, and it stays)

〔已确立·已落在 `page_*`，尚未提为正本〕把正本上分散在两处的页眉（`header.top`）
与页内工具条（`.panel.toolbar`）**合成一条**，**两行 + 底缘一条 3 px 进度线，
共 84 px，`position: sticky`**：

| | 高 | 装什么 |
| :--- | ---: | :--- |
| 第一行 | 40 px | 标记 · 页名 · 副标题 ｜ 内部测试警示 ｜ 四页图标 · 主题开关 |
| 第二行 | 41 px | 装置 / 数据源 · 导入 · 导出 ｜ **运行态一行** ｜ 出口按钮 |
| 底缘 | 3 px | 进度线，跑起来才有颜色 |

落法与实测见 {ref}`fylite-visual-asbuilt`：`page_*` 上量得的外壳高是 91 / 91 /
91 / 88 px，与本表的 84 px 之差记在 G-12。

〔理由〕三条，按分量排：

1. ★**它把运行态搬回按键看得见的地方。** F-1 说的那件事：计算键在功能栏里，
   进度与状态在页面工具条上，两者相隔可达五千像素。常驻之后，无论你滚到哪一栏，
   「哪一条栏在跑 · 第几步 · 还要多久」都在屏幕顶上。**这是本条唯一不可让步的
   收益**，其余两条都是附带的。
2. **它把「我在看哪一页」变成常驻信息。** 六千像素的页面上，页名今天只在最上面
   出现一次。
3. **横向预算是现成的。** F-3 后面那段实测：页眉中段的包裹元素有五百多像素是空的，
   把作业那一行并进来不需要向任何人借宽度。

〔已确立·不可回退〕★**工具条上不放计算键。** 每条功能栏自己有一个键，这是
`scenario.js` 明写过的裁定（「no run key here any more — it moved into every bar's
own strip」）：一页有两三条栏，各解各的问题，一个页面级的 Run 只会引出「它跑的是
哪一条」。工具条上的是**运行态**，不是**运行键**——这两样东西长得像，差别是一个
读、一个写。`shell.js` 的 `watchBars()` 正是这样做的：在 ⑤ 槽**命名**正在跑的那条
栏，键留在栏里。

〔工作假设〕**为什么是两行而不是一行。** 一行的横向预算算得出来：标记 32 + 页名与
副标题 213–284 + 警示药丸 326 + 导航 166 ≈ 880，余 700；而作业那一行要装装置下拉
260 + 导入导出 246 + 出口 120 = 626，**塞得进去，但状态行一个字也不剩**。而状态行
恰好是本条唯一不可让步的那个收益。所以两行。

〔开放猜想〕**滚动时是否收成一行。** 常见做法是下滚后把第一行折起、只留作业行。
本条**不采纳**，理由是页面的空间记忆（`FYL-DESIGN-09` D-19）：一条会变高的带子
会让它下面的一切在滚动中位移。若将来实测证明 84 px 在小窗口下过奢，再按 `V-` 增补。

## V-12 ★四页在外壳上只差三个槽 (three slots, and nothing else)

〔已确立·已落在 `page_*`，尚未提为正本〕外壳共六个槽（见
{numref}`fig-fylite-desktop-shell` 的 ①–⑥），分两类，**判据是它的值从哪里来**：

- **①②③ 取自静态登记表**——页名与副标题、警示、四页图标与主题，都由 `site.js`
  那张页面表一处给出。①的**文字当然逐页不同**（它就是页名），但**没有一页能自己
  决定它长什么样**：换一页只是换表里的一行。
- **④⑤⑥ 取自这一页的运行时**——装置 / 数据源、运行态、出口。它们是页面**此刻的
  状态**，不是登记表里的常量。

沿革一句：v0.3 初稿写的是「①②③ 在四页上逐字相同」，而 ① 就是页名、逐页不同，
故判据改为「值从哪里来」，并由此立下面这条通则。

〔工作假设〕★**外壳只读，页体才写。** 这是 V-11「工具条上是运行态不是运行键」的
一般形式，也是判断「某个控件该不该上外壳」的那把尺：**外壳报告状态，改变状态的
控件留在页体**。放电设计页的三个模式是这条尺的第一个实例——外壳的 ⑤ 槽**说**你
现在在哪一种时间里，切换模式的那三枚键在页体顶上（`FYL-DESIGN-09` D-23，
{ref}`fylite-pulse-design-visual`）。页面一侧的对应条款是 `FYL-DESIGN-10` P-25。

`page_data` 已这样做（外壳高 88 px，首处输出 335 px）。

〔工作假设〕**散文页只有第一行。** 入口、能做什么、致谢没有作业，所以第二行不出现

## V-13 ★16:9 是桌面的定尺，首屏必须落一处输出 (the desktop's own measure)

〔已确立〕**桌面版的定尺取 16:9**，参考视口 **1600 × 900**。理由是它就是这台程序
实际被看的样子：`fylite` 拉起系统浏览器，用户把窗口拉到屏幕大小，而绝大多数
桌面显示器是 16:9。站点排版此前的实测视口是 1440 × 900（16:10），**两者并存**：
1440 × 900 是文档面的历史基线，1600 × 900 是桌面外壳的。

〔已确立〕**判据一条，可机器判：功能页面在 16:9 首屏内必须至少呈现一处输出。**
输出＝一幅图、一张读数表或一处解出来的数——**不是**引言、不是工具条、不是输入控件。
闸子 `app/tests/validate-page-v2.mjs`〔三〕按「首处输出的 `offsetTop < 900`」断言，
在 `page_*` 四页上成立（297 / 790 / 336 / 335 px，G-10 已闭）；正本上仍不成立。

〔理由〕F-3 实测四页里三页不满足：设计页与数据页整整 1500 px 内一处输出也没有。
一个计算工具第一屏全是散文与滑块，读者要先向下滚过一屏半才知道这一页会画出什么。
★而这一条与 V-3（首屏两种任务）**不冲突而是收紧**：V-3 说桌面读者已经知道这是
什么，所以首屏该给的是入口与作业面；V-13 给出那句话的可判形式。

〔已确立〕**怎么满足，本篇不规定**——那是四份页文档的事（V-15；页面一侧的条款是
`FYL-DESIGN-10` P-26、`FYL-DESIGN-09` D-24）。能想到的路子至少三条：引言收成可折叠
的一段（默认折起，`FYL-DESIGN-09` D-19 的折叠约定已有）；共用输入控件与第一条
功能栏并排而不是上下；第一条功能栏默认展开且带一张**空态图**（画出坐标轴与它将要
画的东西，而不是一片空白）。`page_*` 走的是第一与第三条（`shell.js` 的 `foldLead()`
与 `emptyState()`）加第二条的一种形式（`sideColumn()` 把共用面板放到栏的旁边）。

〔工作假设〕**判据只在定尺那一档成立。** 1280 × 720 下建模页的首处输出落到
1029 px（{ref}`fylite-visual-asbuilt` 的 warning）；窄档的落法另议，记在 G-3。

## V-2 ★桌面里说错了的话，必须改口 (the sentences that are false on the desktop)

〔已确立·实测〕同一份页面在桌面语境下的自述有**假的**。2026-09-04 按仓树复核，
三处里两处仍在（`app/index.html` 的 `<title>`、`<h1>` 与引言），第三处已随
Node 网关退役而消解：

| # | 页面上的原话 | 为什么在桌面里是假的 | 2026-09-04 |
| :--- | :--- | :--- | :--- |
| ① | `<h1>fylite 在线演示</h1>` / `fylite online demos` | 桌面查看器**离线**运行，字节来自可执行体自己。「在线」在这里字面为假，而它还是全页最大的一行字 | **仍在** |
| ② | 「全部计算在本机浏览器内完成，**无需安装、无需服务端**」/「nothing to install, **no server involved**」 | 桌面里**有一个服务端**——就是这个可执行体本身。计算确实仍在浏览器里（这半句是真的），但「无服务端」不是 | **仍在** |
| ③ | 数据页曾先给 `node app/server/gateway.mjs …`、再给 `--mdsip` 那条路 | 桌面里不必另起 Node 进程：同一个可执行体带 `--mdsip` 就同时是页面与请求面（`FYL-REPORT-05` §3b.5）。次序与默认错了，桌面读者按顺序照做就多起一个进程 | **已消解**：`app/server/` 已退役（数据页源码注记 2026-09-01），今天页面只写 `fy --mdsip 127.0.0.1:8000` 与隧道命令 |

沿革一句：v0.1 / v0.2 把 ③ 写成「桌面里那个网关不是另起的 Node 进程」并据此说页面
会误导读者，v0.3 更正为「真正成立的是次序与默认」；现在连次序问题也随退役消失，
本条剩 ①②。

〔工作假设〕**改法：一句话由宿主决定，而不是两份页面。** 页面在运行时能知道自己
在哪——桌面宿主答 `/api/health`（**即使没给 `--mdsip` 也答**），站点上这个端点
**不存在**。据此把这两处写成**由宿主填的槽**：

- 标题：站点「在线演示」／桌面「本机查看器」；
- 引言那半句：站点「无需安装、无需服务端」／桌面「本机运行，字节来自这个可执行
  文件自己；计算仍在浏览器内」。

〔理由〕**为什么不做成两份页面**：两份就会漂。这一整套文档反复记的就是那种失败
（`FYL-DESIGN-10` P-14、`FYL-DESIGN-09` D-20），而这里的两份还各有中英两版，
一处改动要同步四个地方。一个由宿主填的槽只有一处。

〔已确立〕**探测必须是「有没有」，不是「是不是本机」，而且这一半已经落地。**
`assets/host.js` 在回环地址上探 `/api/health`，把结果写成 `<html data-fy-host>`；
主机名只作**否定过滤**（查看器只绑回环且不可配置，所以非回环一定不是它，站点因此
一个请求也不发）。V-7 已经用上了这套；**V-2 自己的文案那一半仍未落**
（{ref}`fylite-visual-g1`）。

## V-3 首屏：桌面是「打开就干活」，站点是「先说清这是什么」 (two jobs)

〔工作假设〕两个语境下首屏的任务不同，且这个不同**不是审美偏好**：

| | 站点版 | 桌面版 |
| :--- | :--- | :--- |
| 读者是谁 | 多半**第一次**看到，从链接来 | **主动下载并双击**过，已经知道这是什么 |
| 首屏该给 | 这是什么 · 凭什么可信 · 边界在哪（logo · 引言 · alpha 提示 · 四张卡） | **入口与作业面**：四页各一张卡，外加「上次看的那一页」 |
| alpha 提示 | 必须在首屏——他还没决定要不要信 | 保留但可收成一行——他已经下载了 |

〔工作假设〕**改动很小，这是要点。** 桌面版不换首页，只做三件事：把四页的卡片
**提到 hero 之上**、把 alpha 段落收成外壳上的一枚芯片、在卡片区加一枚「继续上次」。
★页面的**空间记忆**是最便宜的资产（`FYL-DESIGN-09` D-19 的同一条），所以**不重排**
其余部分。功能页面的首屏则由 V-13 的判据管。

〔开放猜想〕「继续上次」要不要落地，取决于 `localStorage` 在桌面语境下的行为是否
稳定（每个端口一个 origin——`--port` 变了记忆就没了）。这条**未验证**，标
`[TBD]`：与其给一个时灵时不灵的入口，不如先不给。

## V-4 导航栏在桌面里少一个方向 (the nav loses one direction, and gains none)

〔已确立〕外壳第一行右端今天是：四页图标 + 主题开关（166 px）；标记本身就是回入口
的链接，所以没有第二个「首页」项。桌面版**全部保留**——`app/guide/`、三张散文页、
四页场景与工具页、算例与装置牌**都在可执行体里**（89 个资源），所以离线导航是完整的。

〔工作假设〕唯一该变的是**出站链接的呈现**：桌面里点一个指向公网的链接，会跳出
这个查看器、进另一个标签页，而**用户可能根本没有网**。这类链接（上游仓库、论文

工作，这不是缺陷**。

〔理由〕不加标记的代价是具体的：一个在离线机器上点开后白屏的链接，读起来像页面

缺失的进程，而不是画一张空图）。

## V-6 身份带在桌面里多一格：它在哪儿跑 (the identity strip gains one cell)

〔工作假设〕页脚身份带今天六样：标记 · 其他页面 · 语言 · 版权 · **版本片** ·
二维码。桌面版**加一格**：`本机 · 127.0.0.1:<port>`。

〔理由〕三条，都实用：

1. **它回答「我在看哪一个」。** 同一台机器上可以同时开着站点标签页与一个（或
   几个）不同端口的查看器；页面看起来一模一样。
2. **它是排障的第一格。** 数据页面板禁用时，第一个问题永远是「你连的是哪个」。
3. **它与版本片是同一类信息**：版本片说「这份字节是哪一版」，端口格说「这份字节
   从哪来」。二者并排，出处才完整（`FYL-DESIGN-10` P-13）。

〔工作假设〕**它只在桌面语境下出现**（探测同 V-2），站点上不留空格。

〔工作假设〕**为什么在页脚而不在外壳上。** 外壳那两行装的是**你要用的东西**；
「它在哪儿跑」是出处，和版本片、版权是同一类，属于身份带。这条分工与 V-12 的
「三个槽」一起，构成外壳的收纳判据：**能操作的进外壳，说明来历的进身份带**。

# 不随宿主改变的那一层 (What the Host Does Not Change)

(fylite-visual-v5)=
## V-5 主题三态开关照旧，理由一字不改 (the three-state theme switch stays)

〔已确立〕三态（跟随系统 / 明确浅色 / 明确深色，**明确的一方永远赢**）在桌面版
**不变**。那段裁定的理由与投递面无关：**这些页面上的图会被截进论文、投在亮着灯的
房间里**，而一张背景跟着操作系统走的图，导出来的图片是不可复现的；答案是给出
**选择**（导图的人拨到 ☀ 浅色，每次得到同一张图），而不是取消开关。**绝不能回来的
是**：一个只因为操作系统是深色所以深色、且无从更改的页面。

〔工作假设〕桌面版**唯一**的差别是**首次启动的缺省**：站点第一次访问跟随系统，
桌面第一次启动**也**跟随系统——**这一条明写出来是为了防止有人在桌面上钉死浅色**
（「桌面应用嘛，白底更像原生」）。那会让同一份图在两个投递面上导出不同的背景，
正是这条裁定要防的事。

(fylite-visual-v8)=
## V-8 物理量的颜色是数据语义，不是主题装饰 (those six colours are data)

〔已确立〕`--lcfs`（最外闭合磁面）· `--coil`（线圈）· `--wall`（真空室 / 限制器）·
`--flux`（磁通面）· `--alt`（第二序列）· `--grid`——这六个 token **不是配色偏好**，
它们在概念图与四页的画布上是**同一件事的同一个颜色**。改一个，改的是所有页面
上那一类对象的身份。

〔工作假设〕由此三条，在桌面版与站点版**同样成立**：

1. **明暗两套必须各自成对**：深色下 `--lcfs` 由 `#d0342c` 换成 `#ff7b6b` 不是
   「调亮一点」，是让**同一个对象**在两种主题下都可辨且仍然是「那个红」。
2. **不得为了好看借用它们**。一个用 `--coil` 紫来强调按钮的页面，等于告诉读者
   那个按钮是线圈。
3. **色不是唯一的编码**。判定类信息（越限 / 未收敛 / 已解 vs 插值、以及 V-12 的
   四种运行态）必须**同时**有文字或字形差别——这既是无障碍要求，也是本仓一贯的
   立场：一个只靠颜色说「这条没收敛」的图，在灰度打印后就什么也没说
   （`FYL-DESIGN-09` D-8 / D-25 · `FYL-DESIGN-10` P-5 / P-27）。提案 NR-QUAL-004
   的正本在本篇，`-10` / `-12` / `-13` 引用。

(fylite-visual-v9)=
## V-9 字级级数与行长照旧，桌面不放宽 (the scale and the measure do not widen)

〔已确立〕文档面的字级取自 16 × 1.2ⁿ 的级数 {13, 16, 19, 23}，外加 **14** 一档
表格特例（13 px 中文四列表读不了，16 px 撑破列宽）；文本列宽 `--measure: 44rem`。
这两条由 `validate-typography.mjs` 守着，理由记在内核仓实测笔记
`docs/note/app-typography.md`：文档面曾累积到 **十个**字号（12.5 / 13.5 / 14.5 /
15.5 都在其中，跨度 1.42 倍），且 `h3` **比它所标的正文还小**——没有人决定过那样，
它是半个像素一次长出来的。

〔工作假设〕桌面窗口通常比站点访问更宽（用户会把它拉大），**但文本列不跟着变宽**。
以中文为主语言定尺，每行 40–45 全角字；窗口变宽时**变宽的是图、表与画布**，
不是散文——这正是 Distill 的做法，也是仪器面与文档面分开的意义所在。

〔已确立〕仪器面（面板 · 工具条 · 读数 · 图注）的 12–13 px **不在这条之内**，
门禁也明写它对仪器面没有意见：那是仪表的字号，不是文章的字号。**外壳整条属于
仪器面**——它的 12–15 px 不受 V-9 约束，也因此不该由 `validate-typography.mjs` 判。

(fylite-visual-v10)=
## V-10 桌面版仍然不引 Web Font (offline is not a licence to ship fonts)

〔已确立〕`app/` 不 vendor 第三方资源，且要能在受限网络下工作；一套中文 Web Font
是**数 MB** 的子集化工程。桌面版看似解除了「不能外链」的顾虑（字节都在包里），
但它引入了一个更硬的：**5.3 MB 的可执行体里塞一套中文字体，体积会翻倍以上**——
而 5.3 MB 正是这条通道相对 Electron 的全部优势。

〔已确立〕现字体栈（拉丁在前、CJK 在后回退）**是对的，不要动**；中文屏幕正文用
宋体在小字号下笔画细、渲染差，通行做法仍是黑体 / 无衬线。

〔已确立〕**中西文之间的 1/4 em 间距只能缓解、不能根治**：CSS 的 `text-autospace`
尚未在任何主流浏览器落地；三个选项（什么都不做 / 在 1158 条词条里手写细空格 /
运行时插 JS）里取**什么都不做**，并把这一条记在案上，等 `text-autospace` 可用时
一行开启。桌面版**不改这个判断**——渲染引擎仍是用户的浏览器，能力集完全一样。

(fylite-visual-v14)=
## V-14 预览图是生成物：16:9、不带固定尺寸、闸子守着 (generated, and scalable)

〔已确立·已落地〕本篇的五张预览图由 `tools/make-desktop-preview.py` 生成，
提交进仓（`docs/figures/desktop-{shell,data,pulse-design,model,analysis}.svg`），
`python/tests/test_desktop_previews.py` 守三件事：

1. **与生成器一致**（`--check`，与 `make-app-pages.mjs --check` 同一形状）。
   一张手改过的图，或一个改了却没重跑的生成器，会把**两版之前有人主张过的布局**
   留在页面上，而它引用的数字仍在正文里被当作实测——**这正是本套文档反复记的那
   一种失败**。
2. **`viewBox` 是 16:9**。这里的 16:9 不是装饰：它是桌面查看器自己的定尺，
   这些图争论的那条折线是**这个框里的** 900 px（V-13）。换个比例就是换了个论断。
3. **根元素不带 `width` / `height`**。带了，SVG 就有了固有尺寸，也就**不再随容器
   缩放**——而「可缩放」正是本条要的性质。

〔已确立·用户裁定 2026-09-01〕★**预览图只有明亮一套配色，不跟随系统。** 五张图里
**没有** `@media (prefers-color-scheme: dark)` 那一段，取值是 {numref}`tbl-fylite-visual-baseline`
的浅色一列。

〔理由〕这看起来与 V-5（主题三态）相反，其实是**同一条理由推到底**：V-5 之所以给出
明确的开关，是因为**这些图会被截进论文、投在亮着灯的房间里**，而背景跟着操作系统
走的图导不出可复现的图片。页面可以把选择交给读者，**一张图不能**——它没有开关，
读者拿到的就是渲染它的那台机器当时碰巧的偏好。所以页面三态、图定死浅色，两者要的
是同一件事。

〔已确立〕★**同一仓里的另一个图生成器 `tools/make-app-figures.py` 在这两点上都是
相反的做法**（它写 `width` 与 `height`，也带深色段）。那是**有意的**：那批是高瘦的
整页线框图，有自然尺寸；本条只管 `desktop-*.svg` 这五张。写在这里并记在生成器的
注释里，是因为下一个人照着旁边那个文件抄，会把固有尺寸带回来，而没有任何东西会
因此变红——除了上面那第三条。

〔已确立〕★**它们按 1600 × 900 的真实像素画，因此在文档栏里偏小。** 实测本书正文
栏宽 727 px，图落在 727 × 409——结构（那条带子、四条柱、折线）读得出，**10–12 px
的注记读不出**。这是本条选 16:9 的代价，且**不打算靠放大字号补**：字号放大就不再是
这条带子实际的样子，而「实际的样子」正是一张界面预览图的全部内容。要看细节就直接
打开文件（矢量，放到多大都不糊）：`docs/figures/desktop-shell.svg` 及同目录另四张。

〔已确立〕**它们是概念图，不是截图。** 那条工具条按 V-11 的形状画，不是从 `page_*`
截来的；正本页面上它今天仍不存在。四页的页体按各自文档已裁定的结构画，曲线是示意
形状、不算物理。图内页脚每张都写着这句。**真正实测的是** {numref}`fig-fylite-desktop-shell`
下半那四条——页高与偏移取自 {numref}`tbl-fylite-shell-measured`，两处同源。图与
`page_*` 之间今天没有闸子（G-12）。

〔工作假设〕**生成器先解析再落盘。** `write()` 在写文件之前用 `ElementTree` 解析

XML 错误框，而**下游没有任何一步会读 SVG 的内容**——它只被当作字节复制、当作
`<img>` 引用。这是「无声失效」的又一例，处置是让生成器自己成为那个读者。

# 不可回退的几条与门禁 (What Must Not Regress, and What Guards It)

〔已确立〕下列每一条背后都有一次实测或一次已付过的代价，**桌面版不是重新讨论它们
的场合**：

| 不可回退 | 它挡住的那次失败 |
| :--- | :--- |
| 主题三态，明确的一方赢 | 一个只因操作系统是深色所以深色、无从更改的页面——导出的图不可复现 |
| `--muted` / `--warn` 的现值 | 原值在 `--bg` 上是 4.34 / 4.17，**低于 AA**；而 muted 在这里是正文（表头、注、卡片副标题） |

| ★**外壳的差别用运行时槽表达，不做两份页面** | 两份就会漂，而它们还各有中英两版——一处改动要同步四个地方（V-2 · V-7 的同一条） |

:::{note} Rationale
桌面版没有给 fylite 一套新的视觉语言，它给的是一个**新的语境**——离线、本机、
一个已经决定要用它的读者。本篇因此绝大部分仍在说**不要改什么**：主题三态、色板的
语义绑定、字级级数与行长、不引 Web Font，每一条都是一次已经付过的学费。

真正加进来的是**外壳**，而它的理由不是整洁，是一次实测：**这套页面上没有一样东西
是常驻的**。页眉与工具条都是 `position: static`，而页高在 2212 到 6364 px 之间；
于是在建模页上，你按下的计算键与告诉你它在跑的那两样东西相隔五千多像素。一次运行
开始之后没有可见的反馈——这不是版面问题，是**页面对自己正在做的事保持沉默**。
V-11 要的就是这一条，其余（页名常驻、横向预算宽裕）都是顺带。它已经落在 `page_*`
上，而正本未动——两套并存的代价是几个文件，收益是每条改动都量得出差别。

第二件是 **16:9 与那条首屏判据**。四页里三页的第一屏是引言、工具条与滑块，一个数
也没有。定尺写出来、判据写成可机器判的形状，是为了让「首屏该有什么」不再是审美
争论。

第三件是**预览图的纪律**：它们是生成物，`--check` 守着，`viewBox` 是 16:9、
不带固定尺寸。而生成器第一次运行就自己抓到一处**无声失效**——一个少了引号的属性，
浏览器会把整张图渲成红色错误框，而下游没有任何一步会读 SVG 的内容。这是本套文档
反复记的那一类：**一份东西没有任何读者，就一定会烂，而它烂掉时不会有任何东西变红**。
处置每次都一样——让某个东西成为它的读者。
:::
