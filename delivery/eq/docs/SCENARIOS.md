# 计算场景分类评审

> 评审对象：`ui/magnetic-live.html` 的「建立分析对象」面板与 `ui/assets/magnetic-live.js`
> 的 `ruleDraft / draftIssue / updateSceneState / renderScene`。
> 结论先说：现有分类**混用了三个不同维度的概念**，并且**有一半选项选了也跑不了**，
> q₀ 完全没有位置。建议按「任务 / 数据来源 / 约束集」三轴重整。

## 一、现状

| 字段 | 取值 | 备注 |
|---|---|---|
| `scenario` | `magnetic` / `geometry` / `physics` / `fixed` | 下拉框 |
| `pressure-source` | `unconstrained` / `imported_total` / `diagnostic_thermal` / `thermal_plus_fast` | 仅反演 |
| `pressure-constraint` | `soft` / `fixed_shape_scaled` / `fixed_values` | 仅在压力非"无"时出现 |
| `current-source` | `free_pprime_ffprime` / `bootstrap_plus_residual` | 仅 `physics` |
| `mask` | `m02_pinned` / `device_default` | 仅 `magnetic` 且压力为"无" |
| `grid` | 33 / 65 / 129 | 仅正向 |
| `class`（派生） | `single_pass` / `remap` / `source_feedback` / `forward_fixed_boundary` | `classify()` 由 scenario+updates 推出 |

真实可运行范围（`runnable`）：

```js
runnable = scene === 'fixed' || (scene === 'magnetic' && pressure === 'unconstrained')
```

也就是 **4 个场景里只有 2 个能跑**，且反演侧唯一可跑的是"纯磁、无压力"。

## 二、问题

### 2.1 任务类型与外环更新混在一个下拉

`scenario` 的四个取值里：

- `fixed` 是**另一种任务**（正向计算）；
- `magnetic` / `geometry` / `physics` 是**同一个任务下的三种外环更新范围**。

两者语义层级不同，却并列在同一个下拉里。派生出来的 `class` 又把它们映射成
`single_pass / remap / source_feedback / forward_fixed_boundary` 四类——
同一个概念在 `scenario` 和 `class` 两处重复表达，容易漂移。

### 2.2 可选 ≠ 可运行

界面上四个场景看起来同等可选，但只有两个能运行。不可运行的三类只在底部用一行小字
提示"仅提供配置草稿；当前没有可运行求解链"。

用户必须先选、再读提示，才知道选错了。**应当在选择时就禁用并说明原因。**

### 2.3 `mask` 与场景耦合，但看不出耦合

`m02_pinned` 不是通用的"通道规则"，它是**某一次历史算例的完整配置**：

- 只在 164437 可用（`updateMask()` 按炮号禁用）；
- 隐含 79 道固定权重 + `EQ-M02` 输入卡（后端 `create` 里单独取 `case_input('EQ-M02')`）；
- 一旦选中，配方与通道权重都随之固定。

它被放在"磁通道规则"里，和"装置默认规则"并列，看不出它是绑定炮号的历史快照。

### 2.4 q₀ 完全没有位置（最大的缺口）

压力有 4 种来源 × 3 种作用方式，电流有 2 种模型，而 **q₀ 连一个字段都没有**，
文案甚至明确写着"本路线不引入压力或 q₀ 目标"。

但事实是：

- `preset` 配方可以钉 q₀（`qpsi(1)=q_target`）；
- 参考 EFIT 的 q₀ 同样来自剖面模型 + `qvfit` 初值；
- 38 探针的早期炮纯磁反演欠定，q₀ 先验是唯一可行的稳定手段。

刚加的 q₀ 面板是**绕过现有分类体系的独立面板**，不在 `ruleDraft` 里，也不参与
`runnable` 判定——这本身就是分类体系缺口的证据。

### 2.5 结果状态没有分类

钉了 q₀ 或压力之后，结果是"受约束反演"，与"独立反演"的可信度不同。
但结果页只有三类状态（`passed` / `physics_gate_failed` / `solver_not_converged`），
**没有"这次结果是否依赖外部约束"的位置**。

现在的审阅规则用了一个隐式替代：
`mask_profile !== 'device_default' || channel_customized`——把"通道是否自定义"当作可信度代理，
和真正的"约束集"并不是一回事。

### 2.6 正向与反演的输入维度不同，靠散落的开关切换

反向要炮号 / 时刻 / 掩码；正向要网格 / 边界 / 源项。
现在由 `renderScene()` 里一连串 `hidden` / `disabled` 控制，
而校验逻辑分散在 `ruleDraft`、`draftIssue`、`updateSceneState` 三处，
新增一个维度（比如 q₀）就要同时改三处。

## 三、建议：三轴正交分类

### 3.1 轴一：任务

```
反演（实验炮号 + 时刻）
正向（给定边界 + 源项）
```

只有两个值，替代现在混着外环更新的 `scenario`。

### 3.2 轴二：数据来源

```
实验测量（炮号 + 时刻）         ← 反演
合成 / 给定（网格 + 边界 + 源项）← 正向
历史配置（如 164437 M02 快照）   ← 独立的一类，不再伪装成"通道规则"
```

### 3.3 轴三：约束集（每个约束独立开关）

| 约束 | 取值 | 现状 |
|---|---|---|
| 磁测量 | 必选（反演） | 已有 |
| 压力 | 无 / 导入 / 诊断合成 / +快离子 | 已有 |
| **q₀** | 无 / 先验值 / 扫描区间 | **新增**（面板已做，待并入） |
| 边界 | 自由 / 固定（EFIT 或给定） | 无 |

### 3.4 结果状态由约束集推出

```
constraints == 空   → 独立反演
constraints != 空   → 受约束反演（列出用了哪些约束）
```

结果页应当显示这次用的约束集，审阅时也按它判断可接受性，
而不是用"通道是否自定义"当代理。

### 3.5 交互原则

1. **不可运行的组合直接禁用**，并在旁边写明原因（"需要 Thomson 数据"、"该配方未接通"），
   而不是允许选择后再提示"仅草稿"；
2. 约束面板每行一个开关 + 参数 + 可用性，新增约束不需要同时改三处校验；
3. 下拉只表达单一维度，不再出现"任务 + 更新范围"混排。

## 四、迁移建议（按收益排序）

| 顺序 | 动作 | 状态 |
|---|---|---|
| 1 | 场景名称加约束括注（单次反演（M · 纯磁）等），说明写明约束/数据/可运行性 | ✅ 已完成 |
| 1b | 场景面板新增「额外约束」区：q₀ 可勾选并填值；POINT / Thomson 标「待接入检查」；MSE 标「EAST 无此诊断」 | ✅ 已完成 |
| 1c | 场景标题旁增加可用性徽标（可运行 / 仅草稿） | ✅ 已完成 |
| 2 | 不可运行的场景/组合改为禁用 + 原因 | 进行中（徽标已做，按钮文案仍是「当前组合尚未接入」） |
| 3 | `scenario` 拆成 `task` + `outer`（或直接并入约束集） | 消除维度混用 | 中 |
| 4 | 结果页显示约束集与"独立/受约束"状态 | 审阅有依据 | 中 |
| 5 | `mask` 改归"数据来源 · 历史配置" | 消除"通用通道规则"的误解 | 小 |

## 五、附：与当前实现的一致性

- 有 `<div id="scene-options">` 与 `sceneSpecs` 可作为三轴改造的落点；
- `ruleDraft()` 已经是"把界面状态翻译成配置"的地方，适合改成"任务 + 约束集"两段；
- 后端 `create` 只接受 `{shot, time_s, mask_profile}`，若增加约束字段需要同步扩展；
- q₀ 面板用的 `archive-magnetic-q0` 已经是"约束驱动的一次运行"，可作为约束集模型的第一个实例。
