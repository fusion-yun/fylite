# 给 fylite_dev 的问题清单

来源：FYLite 磁平衡工作台在 EAST 多炮号上做纯磁重构时暴露的问题。
环境：rc3 发布内核（`libfylite_kernel.so` sha256 `f2632102…`，ABI 163）+ standalone 适配器 `demo.py`。
每条都带可复现的对照数据与源码依据，路径附在节末。

## 问题 1：早期炮号的探针**命名体系**与实际数据树不一致（数量对、名字错）

### 现象

`docs/design/FYL-SDD-03.md`（A-22，第 887–907 行）规定：

> 磁探针命名 ≤97030 为 `\HBP1T` 体系（提供者 `base` / `east`，**38 探针 + 35 环**）、
> ≥97034 为 `\HBPH1T` 体系（`east_new`，79 探针 + 75 环）

按这条规则，早期炮号取到 38 路，名字是 `HBP1T … HBP38T`。

但实际数据树（以 #94048 为例）里，这 38 个位置的节点名是：

```
idx  0..2   HBP1T, HBP2T, HBP3T
idx  3..7   NHBP4T, NHBP5T, NHBP6T, NHBP7T, NHBP8T
idx 24..25  DBP25T, DBP26T
idx 26..28  NHBP27T, NHBP28T, NHBP29T
idx 29      NHBP31T
idx 30..33  HBP32T, HBP33T, HBP34T, HBP35T
idx 34      DBP36T
idx 35..37  HBP37T, HBP38T, HBP1N
```

按 `HBP{n}T` 顺序取数的后果：

- **9 路读到 0**（索引 3,4,5,6,7,26,27,28,30）；
- **索引 29 之后整体错位一格**：`HBP30T` 读到 −1.31 T，EFIT 期望 −0.156；
- `HBP34T` 与对应真值**符号相反**。

### 证据：与 EFIT 自己的输入卡逐点对照

### 影响范围

所有走 `\HBP1T` 体系的炮号（≤97030）。实测 #94048、#95045、#96000 都是同样的 9 路读 0。

### 后果（实测）

|---|---|---|
| 94048 / 5.76 s | χ² 1.9e5–2.8e5，`没有一个竖直设定点收敛` | 仍未收敛（见附二） |
| 94048 / 4.21 s | 未收敛 | **收敛**，q₀ 1.933 / q₉₅ 3.749 / χ² 81.6，磁轴 R 1.870（EFIT g 文件 1.881） |
| 94048 / 3.00 s | 收敛（q₀ 2.120） | 同前 |

### 请求

1. **确认 A-22 里“≤97030 = `\HBP1T` 体系”指的是命名规则还是树节点名**：
   - 若是命名规则（`HBP{n}T` 只是逻辑编号），设备事实需要给出**逻辑编号 → 实际节点名**的映射；
   - 若指树节点名，则 A-22 与实测不符，需要更正。
2. 在早期提供者页面逐通道写明实际节点名；缺失的（如 `\HBP4T`）应标 `fylite:absent`，不要让消费方读到 0 而误认为有值。
3. 磁通环（35）与 PF（12）本次实测都对，但同属一个提供者页面，建议一并复核。

## 问题 2：扫描失败时的错误信息不可诊断

### 现象

内核返回的 `tiers.M` 里已有完整的逐候选扫描记录：

```json
"rounds": [{"round": 0, "scan": [
   {"zc": -0.03,  "chi2": 335390.0, "q0": 0.107, "converged": false},
   {"zc": -0.026, "chi2": 167690.0, "q0": 0.118, "converged": false}
]}]
```

而 `tiers.M.error` 只有一句：

```
"没有一个竖直设定点收敛"
```

### 问题

同一句话对应三种完全不同的成因，仅凭 `error` 无法区分：

1. 通道名错配（问题 1）；
2. 求解选项配置错误（`options.loops = 'all'` 强制纳入坏道）；
3. 该时刻数据确实无法约束平衡。

### 建议

- `error` 里带上候选数量与首个失败原因，例如 `16 个候选全部未收敛，首个 zc=-0.03 chi2=3.4e5`；
- 或在 `tiers.M` 增加 `error_class`，区分 `scan_no_convergence` / `channel_inconsistent` / `solver_refused`。

## 问题 3：发布包不含纯磁适配器，导致双内核并存

### 现象

`v0.0.1-alpha-rc3/eq` 里有 `lib/libfylite_kernel.so`（`f2632102…`），但**没有** `demo.py`、`facts/`、`input/`；
纯磁工作流需要这些，原本指向 `artifacts/standalone-v3-20261027`，用的是另一份内核（`84d31c8d…`）。

即：界面在 rc3 上，计算却在另一套内核上，rc3 的内核修复进不了纯磁路线。

### 已做的处理（应用侧）

用 rc3 内核重建适配器包：

```
artifacts/standalone-rc3-20261028/
    libfylite.so = rc3/lib/libfylite_kernel.so   f2632102…
    libsp.so     = rc3/lib/libsp.so              0170a30c…
    demo.py / facts/ / input/  ← 来自 standalone-v3
```

三处哈希已对齐：包内 `MANIFEST.sha256.json`、`archive_v3.py:EXPECTED_LIBRARY`、`demo.py:LIB_SHA`。

### 验证

rc3 内核与旧内核在本路线上**数值完全一致**：七个算例逐项相同，含 164437/6.301 = 262 次 / q₀ 2.69601 / χ² 364.468。

### 建议

- 把纯磁适配器纳入 rc3 发布，或由发布流程产出一份与 rc3 内核绑定的适配器包；
- 否则每次内核升级，应用侧都要手工重建一次适配器包，容易退回旧内核（本次就是这样）。

## 附一：weight 与 σ 的定义（源码依据，非缺陷）

`weight` 是乘在 `1/σ` 上的系数：`weight = 1` 表示“按该通道的 σ 信任”，`0` 表示不参与拟合。

```
src/door/case/kinetic/native_solver/bin/pressure_matrix.rs:31
    row[12 + j] = (span / area * integral[j]) / sigma[i] * weights[i]
src/door/case/kinetic/x.rs:199
    kv_set(&mut st, "q0_weight", Val::F64(1.0 / sigma));
```

σ 由 `demo.py` 计算（不来自设备卡）：

```
demo.py:21-25
    σ = max(SERROR·|读数|, 位下限)   SERROR = 0.05
    LOOP_FLOOR  = 5e-4      # Wb/rad
    PROBE_FLOOR = 7.5e-4    # T（KEFIT efit/2016/bitmp2.txt 的中位）
demo.py:737
    fwtmp2[i] = 0 if 通道被弃用 else (设备卡 weight if 有 else 1.0)
```

**结论**：早期设备卡没有 `weight` 字段 → 全部取 1.0，是设计行为，不是缺陷。
只需在文档里补一句“`weight` 是 `1/σ` 的乘数”，避免集成方把 `bitmp2` 的 σ 直接当权重（那等于二次加权，实测 χ² 会冲到 1e9–1e16）。

## 附二：94048 / 5.76 s 仍未收敛——已排除与仍存疑

修复探针命名后，94048 / 4.21 s 收敛且磁轴与 EFIT 吻合（1.870 vs 1.881 m），但 **5.76 s 仍然 `没有一个竖直设定点收敛`**。

### 已排除

| 假设 | 做法 | 结果 |
|---|---|---|
| 竖直扫描范围不够 | ±0.10 / ±0.20 / ±0.30 m 三档，各 21 个候选 | 全部失败，χ² 7.9e4–1.4e6 |
| 个别离群通道 | 把最大探针 `HBP30T`（−1.31 T）权重置零 | 仍失败 |
| 探针节点名 | 按实际节点名回填（问题 1 的修复） | 探针值与 EFIT 逐点吻合，4.21 s 成功、5.76 s 仍失败 |
| 输入卡 `btor` / `target_ip` | 与 EFIT 一致（−1.608 / 488492） | 无影响（该路径不读这两个字段） |
| 探针权重 | —— | **该假设不成立**，见附一：权重本来就是 1.0，σ 由读数算出 |

### 仍存疑

1. **EFIT 的 m 文件里没有磁通环数据**（`BRSP` 是 12 路 PF 电流），无法用同一份输入核对我们 35 路环读数。若 5.76 s 的环信号存在系统偏差，纯磁拟合会失真。
2. 5.76 s 是否处于位形快速变化或有 MHD 活动的阶段。EFIT 在该时刻磁轴 z=0.033（4.21 s 为 0.038、5.9 s 为 0.037），静态平衡假设是否成立需判断。
3. 同一提供者的探针在 4.21 s 能收敛、5.76 s 不能，差异只在时刻。

### 请求

给一次「同一时刻、同一组测量、EFIT 与内核逐通道残差」的对照，或提供该时刻 EFIT 的磁通环输入值（`flx` 一类），以便判定是环的问题还是该时刻本身不可重构。
